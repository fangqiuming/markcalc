# MarkCalc — Documentation

> Obsidian plugin for **spreadsheet-style formulas in Markdown tables**, built
> around one core rule: **formulas and results live as plain, portable Markdown**.
> The note is self-contained and renders correctly in any editor; **cross-note
> references** (§6.4) are optional and preserve portability because they read the
> values already written, not the logic.

- **Plugin ID:** `markcalc`
- **Version:** 0.10.0 · `minAppVersion` 0.12.0 · desktop and mobile
- **No external dependencies:** the engine evaluates with native JavaScript.

> **New to MarkCalc?** Don't memorize the functions. Turn on the **Editor helpers**
> (§12): while you type inside a `<!-- calc: -->` comment, autocomplete shows each
> function with its **description and example**, and completes **column and note
> names**. It's the fast way to learn it.

---

## 1. Core idea (portability)

| Piece | Where it lives | Visible outside Obsidian |
|---|---|---|
| Table data | Markdown cells | yes |
| **Computed results** | Markdown cells | **yes** (real values) |
| **Formulas** | `<!-- calc: ... -->` comment | yes (harmless comment) |
| **User functions** | ` ```calc-functions ` / ` ```calc-js ` blocks | yes (text in the note) |
| **Cross-note dependencies** | `padres` property (wikilinks) in frontmatter | yes (text in the note) |

Since everything is text inside the `.md`, you can move the note to another vault,
to GitHub or to another editor and **the values and formulas are still there**. The
plugin is only needed to **recalculate**, not to read.

> Cross-note references (§6.4) are **opt-in**: they only appear if you use
> `xcell`/`xcol`/`xlookup`/`xfm`. Even then the note stays readable outside Obsidian,
> because what's read from the other note are its **already-written values**.

## 2. Installation

Copy the plugin folder into your vault:

```
<your-vault>/.obsidian/plugins/markcalc/
├── main.js
├── manifest.json
└── styles.css
```

Then: **Settings → Community plugins** → enable **MarkCalc**.

> `engine.js`, `wrapper.js` and this README are **source/reference** and are not
> needed in the vault. `main.js` is generated by concatenating `engine.js` +
> `wrapper.js` (do not edit it by hand).

## 3. Basic syntax

Write a normal table and, **on the line immediately below it**, a `<!-- calc: ... -->`
comment with the formulas:

```text
| Product | Qty  | Price  | Total |
|---------|-----:|-------:|------:|
| Coffee  | 2    | 3.5    |       |
| Tea     | 4    | 2.0    |       |
<!-- calc: $Total = $Qty * $Price -->
```

On recalculation, the `Total` cells are filled in. The formula stays in the comment
(it's the source of truth; it always recalculates from there, never from the value
already written, so it's **idempotent**).

### Triggering recalculation

1. **While editing** the note (if "Recalculate while editing" is on).
2. **Manually** from the command palette (`Cmd/Ctrl+P`): **"MarkCalc: Recalculate
   tables (current note)"**.

## 4. References inside formulas

| Reference | Meaning |
|---|---|
| `$Column` | Value of that column in the **current row**. |
| `${Column with spaces}` | Same, for names with spaces **or accents** (`${Artículo}`). |
| `col("Column")` | **Array** with the whole column (for aggregates). |
| `Column(N)` | A **specific cell**: column `Column`, row `N` (1-based, below the header). |
| `cell("Column", N)` | Same as `Column(N)`, but works for **any** name (spaces, symbols like `% of total`). |
| `row` | Current row index (starts at 1). |

Column names are **case-insensitive**. Numeric cells are converted to numbers;
empty ones are `0`.

> Watch out for accents: `$Artículo` only captures `$Art` (the `í` breaks the name).
> For columns with accents, spaces or symbols use the `${Artículo}` form.

Multiple formulas are separated with `;` (or across several contiguous comment lines):

```text
<!-- calc: $Total = $Qty * $Price ; $Pct = round($Total / sum(col("Total")) * 100, 1) -->
```

Formulas run **in order**, so `$Pct` already sees the `Total` column computed by the
previous formula.

### 4.1 Cell-targeted formulas

Besides column formulas (`$Col = ...`, which fill **every** row), you can write a
formula for **a single cell** using `Column(N) =`:

```text
<!-- calc:
  Qty(4) = Qty(1) + Qty(2) ;
  Total(4) = Total(1) * WithVAT(2)
-->
```

`Qty(4)` means "column **Qty**, row **4**" (counting data rows below the header). A
cell formula **overrides** whatever a column formula put in that cell, so **order**
matters: put it after.

For columns with spaces or symbols use the universal form:

```text
<!-- calc: cell("% of total", 1) = cell("% of total", 1) + cell("% of total", 2) -->
```

### 4.2 Automatic table expansion

If a cell formula targets a row that **doesn't exist yet**, MarkCalc **creates the
missing rows** (blank) up to it:

```text
| Item | Qty | Price |
|------|----:|------:|
| A    | 2   | 10    |
| B    | 3   | 5     |
<!-- calc: Qty(6) = 99 -->
```

→ The table grows to 6 rows; rows 3, 4 and 5 stay blank and row 6 gets `Qty = 99`
(the other columns of that row blank). From there you can fill them with more
formulas or by hand.

### 4.3 Relative references and running totals

To avoid writing one formula per row (e.g. a **running balance**), there are
functions aware of the current row, valid in column formulas:

| Function | Meaning |
|---|---|
| `up("Col")` | Value of `Col` in the **previous row** (`up("Col", k)` = `k` rows up). |
| `down("Col")` | Value of `Col` in the **next row** (`down("Col", k)` = `k` rows down). |
| `runningSum("Col")` | **Running total** of `Col` from row 1 to the current one. |
| `cell("Col", row - 1)` | Equivalent to `up("Col")` using the `row` variable. |

So the four redundant lines:

```text
Balance(1) = Net(1) ; Balance(2) = Balance(1) + Net(2) ; Balance(3) = ... ; Balance(4) = ...
```

become a **single** column formula, equivalent and growing with the table:

```text
$Balance = up("Balance") + $Net
```

or, without self-reference:

```text
$Balance = runningSum("Net")
```

> Column formulas are computed **top to bottom**, so `up("Balance")` already has the
> previous row's value when it reaches the current one. On row 1, `up(...)` is out of
> range and equals `0`.

## 5. Built-in functions

Available in any formula:

`sum`, `mean`/`avg`, `count`, `product`, `min`, `max`, `round(x, n)`, `floor`,
`ceil`, `abs`, `sqrt`, `pow(x, y)`, `exp`, `log`, `log10`, `IF(cond, a, b)`, and the
constants `PI`, `E`.

Aggregates accept an array (`sum(col("Total"))`) or several arguments
(`sum($A, $B, $C)`). Since the language is JavaScript, you can also use native
operators and methods: `$A > 10 ? $B : 0`, etc.

### 5.1 Conditional aggregates

Like a spreadsheet, with a **criterion** (`"active"`, `">10"`, `"<=5"`, `"!=x"`):

| Function | What it does |
|---|---|
| `sumIf(col("Status"), "active", col("Total"))` | Sums `Total` where `Status = active`. |
| `countIf(col("Status"), "active")` | Counts rows that meet the criterion. |
| `avgIf(col("Status"), "active", col("Total"))` | Average of `Total` where it's met. |

If you omit the third column, it operates on the first: `sumIf(col("Age"), ">18")`.

### 5.2 Dates

| Function | What it does |
|---|---|
| `today()` | Today's date in `YYYY-MM-DD`. |
| `days(a, b)` | Days from `a` to `b` (accepts `"2026-06-01"` or a date cell). |
| `dateAdd(a, n)` | Adds `n` days to date `a` and returns `YYYY-MM-DD`. |
| `year(a)` · `month(a)` · `day(a)` · `weekday(a)` | Components (weekday: 0=Sunday). |

> `today()` changes every day, so a note that uses it will recalculate (and rewrite)
> when opened on a different date.

### 5.3 Output formatting

These return **text**, but the value stays numeric for further calculations
(`$1,500.00 * 2` gives `3000`):

| Function | Example | Result |
|---|---|---|
| `money(x, sym?, dec?)` | `money(1500)` | `$1,500.00` |
| `thousands(x, dec?)` | `thousands(1500)` | `1,500` |
| `percent(x, dec?)` | `percent(28.5)` | `28.5%` (no scaling) |
| `format(x, pattern)` | `format(0.286, "0.0%")` | `28.6%` (`%` does scale) |

> Format only **presentation** columns. Internally the number is recovered by
> stripping `$`, commas and `%`, so chaining keeps working.

## 6. User-defined functions

Two levels, **both embedded in the note** (which is why they don't break portability).

### 6.1 One-line expressions — ` ```calc-functions `

For simple reusable formulas. Syntax `name(args) = expression`:

````text
```calc-functions
vat(x) = x * 0.2
withVat(x) = x + vat(x)
margin(sale, cost) = round((sale - cost) / sale * 100, 1)
```
````

Then use them like any function: `$Final = withVat($Total)`.

### 6.2 Full JavaScript — ` ```calc-js `

For complex logic (conditions, loops, dates, tier tables…). The block receives
`exports` (where you register your functions) and `helpers` (the built-ins):

````text
```calc-js
// Volume discount with tiers
exports.discount = function (price, qty) {
  let pct = 0;
  if (qty >= 10) pct = 0.20;
  else if (qty >= 5) pct = 0.10;
  return price * (1 - pct);
};

// You can lean on the built-in helpers
exports.normalized = (x, column) => x / helpers.max(column);
```
````

Use: `$Net = round(discount($Total, $Qty), 2)`.

> **Portability:** since the JS lives in the note, it travels with it. If you copy
> the note to another vault with MarkCalc installed, the functions still work without
> moving any separate file.

## 6.3 Lookup and constants within the same note

Lookups **within the note itself** (between tables) and constants from the note's
**frontmatter**. For references to OTHER notes, see §6.4.

**Frontmatter constant** — `fm("key")`:

```text
---
vat_rate: 0.2
---
...
<!-- calc: $WithVAT = round($Subtotal * (1 + fm("vat_rate")), 2) -->
```

**Lookup in the same table** — `lookup(keyCol, value, returnCol)`:

```text
<!-- calc: $Price = lookup("Code", $Code, "UnitPrice") -->
```

**Lookup between tables of the note.** First name a table with `@name` inside its
comment; then, in another table **below it**, query it:

````text
| Product | Price |
|---------|------:|
| Coffee | 3.5 |
| Tea    | 2.0 |
<!-- calc: @name = prices -->

| Order | Item | Units | UnitPrice | Subtotal |
|-------|------|------:|----------:|---------:|
| P1 | Coffee | 4 |  |  |
<!-- calc:
  $UnitPrice = tlookup("prices", "Product", $Item, "Price") ;
  $Subtotal = $Units * $UnitPrice
-->
````

| Function | What it does |
|---|---|
| `tlookup("table", "keyCol", value, "retCol")` | Looks up in another named table and returns a cell. |
| `tcell("table", "Col", N)` | A specific cell of another table. |
| `tcol("table", "Col")` | A whole column of another table (for `sum`, etc.). |

> The queried table must be **defined before** (above) the one using it, within the
> same note. To read tables from **other notes**, use the `x...` functions in the
> next section.

## 6.4 Cross-note references

Since **0.10.0** a cell can take the value of a table in **another note**.
Portability is preserved: it reads the **already-written values** in the other note
(its Markdown), **not** its logic.

**In the source note (parent):** name the table with `@name` (same as for internal
lookups):

```text
| Product | Price |
|---------|-----:|
| Keyboard | 80 |
<!-- calc: @name = prices -->
```

**In the consuming note (child):** reference the note by its **name** and the table
by its `@name`:

| Function | What it does |
|---|---|
| `xcell("Note", "table", "Col", N)` | A specific **cell** (row N, 1-based). |
| `xcol("Note", "table", "Col")` | A whole **column** (for `sum`, `mean`…). |
| `xlookup("Note", "table", keyCol, value, retCol)` | Looks up a row and returns another column. |
| `xfm("Note", "key")` | A scalar from the other note's **frontmatter**. |

```text
<!-- calc:
  $UnitPrice = xlookup("Price Catalog", "prices", "Product", $Item, "Price") ;
  $WithVAT   = round($Total * (1 + xfm("Price Catalog", "vat_rate")), 2)
-->
```

The note name is resolved like a **wikilink** (basename, relative path). If the note
or table doesn't exist, the function **degrades to `0` / `[]`** without breaking.

### Automatic dependencies (`padres` → children)

When a note uses these functions, MarkCalc **writes a `padres` property** (Spanish
for "parents") into its frontmatter: the list of notes it consumes, as wikilinks.

```text
---
padres:
  - "[[Price Catalog]]"
---
```

- If a note references **none**, the key is **not** added (no frontmatter noise).
- `padres` is derived **only from `<!-- calc: -->` comments**, not from prose or code
  blocks. A note that merely **mentions** `xcell(...)` as an example (this
  documentation, for instance) does **not** gain false dependencies.
- The **children** (who consumes this note) are **not written**: they're derived from
  the inverse index MarkCalc keeps in memory from Obsidian's `metadataCache` — without
  scanning the vault.

**Cascading recalculation.** When you save a source note, MarkCalc recalculates
**only** the notes that have it as a parent (and, transitively, their children), not
the whole vault. A cycle guard breaks `A→B→A` loops and the cascade terminates at a
fixed point (it stops propagating when no value changes).

This is controlled by the **"Cross-note dependencies (parents)"** setting. Turn it
off if you don't want the plugin to touch the frontmatter; you'll lose the cascade
(children update when you open or edit them).

> **Source of truth:** the formulas. `padres` is a **derived projection** the plugin
> rewrites on recalculation; don't edit it by hand.
>
> **Paths and homonyms:** the source note can be in **any folder**. It's resolved
> like a wikilink: by basename if unique, or by path (`xcell("Folder/Sub/Note", ...)`)
> to disambiguate. The dependency graph is keyed by **resolved path**, so two notes
> with the same name in different folders **don't collide**.

## 7. Security (read this)

**MarkCalc treats note content as trusted code.** It's the same model (and the same
risk) as DataviewJS, Templater or QuickAdd. You should understand exactly what it runs.

### What it runs and why it's dangerous

- **`calc-js` runs arbitrary JavaScript** via `new Function`. That code runs inside
  Obsidian (Electron), so in practice it can do almost anything the process can: make
  **network requests** (`fetch`), and depending on the environment, **read or write
  files** or access system APIs. A malicious note could, for example, **exfiltrate
  your vault** to an external server.
- **Formulas are also evaluated as JavaScript** (`<!-- calc: ... -->` uses the same
  `new Function` internally). So **a formula, not just a `calc-js` block, can run
  code** (e.g. referencing `globalThis`/`fetch`). Important: **turning off "Allow
  JavaScript functions" reduces the surface (removes `calc-js` blocks), but is NOT a
  sandbox**: while recalculation is on, formulas are still evaluated as JS.

### When it runs

Recalculation triggers **on opening** the note and **while typing** (if "Recalculate
while editing" is on) and via the **command**. In other words, **just by opening a
note prepared by someone else, its code could run**.

> With **cross-note** on, recalculating a note **reads** the source notes it
> references. Their tables/frontmatter are read as data (their JS isn't run), but
> remember that **saving** a source note recalculates its children, which evaluates
> those children's formulas. Keep the principle: trusted notes only.

### How to protect yourself

- Use MarkCalc **only in trusted vaults and notes** (the ones you write).
- **Distrust third-party notes**: don't open downloaded, shared or template notes you
  haven't reviewed with the plugin enabled.
- To reduce the risk of automatic execution, **turn off "Recalculate while editing"**:
  that way it only computes when you run the command on purpose.
- **Turn off "Allow JavaScript functions"** if you don't use `calc-js` blocks (it
  removes that path, though — as said — it doesn't fully remove formula evaluation).
- If you're going to open a vault you don't control, **disable the plugin** meanwhile.

### Why it's like this

That same evaluation is what gives the power (complex functions you define, all
inside the note and portable). A real "safe mode" would require replacing
`new Function` with a restricted parser; it's on the future-improvements list (see
§10). Until then: **trusting the note is the only real protection.**

## 8. Complete example

````text
```calc-functions
vat(x) = x * 0.2
```

```calc-js
exports.discount = (price, qty) => price * (qty >= 3 ? 0.9 : 1);
```

| Item | Qty | Price | Total | WithVAT | Net | % of total |
|------|----:|------:|------:|--------:|----:|-----------:|
| A    | 2   | 10    |       |         |     |            |
| B    | 3   | 5     |       |         |     |            |
| C    | 1   | 40    |       |         |     |            |
<!-- calc:
  $Total = $Qty * $Price ;
  $WithVAT = round($Total + vat($Total), 2) ;
  $Net = round(discount($Total, $Qty), 2) ;
  ${% of total} = round($Total / sum(col("Total")) * 100, 1)
-->
````

### 8.1 Cross-note example (parent → child → grandchild)

Three chained notes that demonstrate `xlookup`, `xfm`, `xcell` and the cascading
recalculation (included in the `demo/` folder):

- **`Price Catalog`** (root): table `@name = prices` + `vat_rate` in frontmatter.
  No `padres`.
- **`Purchase Order`** (child): `xlookup` pulls the price from the catalog, `xfm` the
  VAT rate. Its `padres` points to `[[Price Catalog]]`.
- **`Monthly Summary`** (grandchild): `xcell` takes the order total. Its `padres`
  points to `[[Purchase Order]]`.

Change a price in the catalog and, on save, the cascade updates the order and then
the summary — without scanning the vault.

### 8.2 Accounting example

Also in `demo/`:

- **`Ledger`** + **`Balance Sheet`**: an accounting sub-ledger (Debit / Credit /
  Balance by nature) feeding a balance sheet with `xcol` + `sumIf`. The `Discrepancy`
  row is a self-check: it's `0` only if double entry balances.

## 9. If "nothing calculates"

1. **Run the command** `MarkCalc: Recalculate tables (current note)` from the palette
   (`Cmd/Ctrl+P`). It's the deterministic way to test.
2. The comment must start **exactly** with `<!-- calc:` (lowercase) and close with
   `-->`. It can span **one or several lines**.
3. The table must have a separator row (`|---|---|`) and the **target column must
   exist** in the header (the result is written into a column, not created).
4. If you reference a column that doesn't exist (case aside) or use an undefined
   function, that cell is left as is. Enable **"Debug logs"** in settings and check
   the console (`Ctrl/Cmd+Shift+I`) for the error.
5. Recalculation triggers on **typing**, on **opening** the note and via the
   **command**. In the active note the result is written through the editor.
6. **Cross-note:** if `xcell`/`xlookup` return `0`, check that the **note name** and
   the source table's **`@name`** match exactly (the `@name` is case-insensitive; the
   note name resolves like a wikilink).

## 10. Current limitations

- Supports well-formed **pipe tables** (header + `|---|` separator).
- `col()`, `cell()` and `Column(N)` refer to the **same table**; between tables of the
  note use `tcell/tcol/tlookup` (§6.3) and between notes the `x...` functions (§6.4).
- Cross-note reads the **already-written values** in the source note (it doesn't
  re-evaluate its logic). The dependency graph is keyed by **resolved path** (homonyms
  in different folders don't collide; use `xcell("Folder/Note", ...)` to disambiguate
  if they share a basename).
- Auto-expansion only **adds** rows; it doesn't trim extra ones.
- The formula comment must sit next to the table (some blank lines are allowed in
  between, but no interleaved content).

## 11. File structure

| File | Role |
|---|---|
| `main.js` | **Generated file** Obsidian loads. Engine + wrapper. Do not edit by hand. |
| `manifest.json` | Plugin metadata (version). |
| `styles.css` | Styles for the editor helpers (autocomplete + hover). |
| `src/engine.js` | **Source** of the engine (pure, no dependencies; testable with Node). |
| `src/wrapper.js` | **Source** of the Obsidian glue (Plugin, EditorSuggest, settings). |
| `src/build.js` | Concatenates `engine` (without exports) + `wrapper` → `main.js`. |
| `src/test/run.js` · `src/test/i18n.js` | Test suites (`node src/test/run.js`). |
| `demo/` | Example notes (drop the folder into a vault and recalculate). |

> **Build (no dependencies).** Edit `src/engine.js` and/or `src/wrapper.js`, then:
>
> ```
> node src/build.js        # regenerates main.js
> node src/test/run.js     # engine tests
> node src/test/i18n.js    # bilingual catalog tests (EN/ES)
> ```
>
> **Never edit `main.js` by hand** — it's overwritten on each build. The tests cover
> the engine and logic; the live editor (autocomplete/hover) is manual testing.

## 12. Editor helpers (autocomplete and cards)

**The easiest way to learn MarkCalc.** Since **0.9.0**, while you type inside a
`<!-- calc: -->` comment, the editor helps you live. Controlled in **Settings →
MarkCalc → "Editor helpers"** (on by default).

### Context-aware autocomplete

Start typing and a suggestion list appears; **each one shows its signature, group,
description and an example**. Press Enter to insert it. Depending on where the cursor
is, it suggests:

- **Functions** from the catalog (52): `sum`, `round`, `sumIf`, `xlookup`, `up`,
  `runningSum`… with their documentation embedded in the suggestion.
- **Columns of the table** above: you pick `$Total` (or `${With spaces}`) instead of
  typing it. **This kills the most common error** — a mistyped column name that
  silently returned `0`.
- **`@name` tables** of the note, inside the first argument of
  `tcol` / `tcell` / `tlookup`.
- **Note names** from the vault, inside the first argument of
  `xcell` / `xcol` / `xlookup` / `xfm`.
- The **`@name`** directive to name the table.

> It only triggers **inside** the `calc` comments; it doesn't get in the way in the
> rest of the note. It uses the `EditorSuggest` API, so it **coexists with Obsidian's
> native autocomplete** (`[[`, `#`, …) without breaking it.

### Hover card

Hover over a function **already written** inside a `calc` and a card appears with its
signature, description and example. Useful to re-read a note (yours from months ago,
or someone else's) without coming back to this documentation.

### Why it matters

MarkCalc's learning curve was steepened by two things: the **invisible namespace**
(~50 functions across 4 scopes — same table, other table `t…`, other note `x…`) and
**silent failure** (a typo returned `0` with no warning). Autocomplete turns that
namespace into a menu you **pick from** (instead of guessing), and completing columns
and `@name`s attacks silent failure at the root.

> **Single source of truth:** the internal function catalog feeds the autocomplete,
> the hover and (as reference) this documentation at once.

### Language

MarkCalc's interface and editor helpers are **bilingual (English / Spanish)**. Pick
the language in **Settings → MarkCalc → "Language"**: Automatic (follows Obsidian),
English, or Spanish.
